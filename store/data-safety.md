# Google Play「資料安全性」表單填寫內容

Play Console → 政策 →「App 內容」→「資料安全性」。以下依表單順序整理，根據 App 目前的實際行為（v0.10.0）。

## 1. 資料收集與分享

| 問題 | 回答 | 理由 |
| --- | --- | --- |
| App 是否會收集或分享任何必要的使用者資料類型？ | **否** | 見下方說明 |

**說明（為什麼可以回答「否」）**

- Google 對「收集」的定義是：資料**從使用者裝置傳送出去**到開發者或第三方。
- 目標、紀錄、設定、錯誤紀錄都只存在手機上。
- 雲端同步把資料存到**使用者自己的** Google 雲端硬碟，由使用者主動開啟，開發者沒有任何伺服器、也拿不到資料。依 Google 的說明，「使用者自行將資料存到自己的雲端帳戶」屬於使用者的操作，不算開發者收集。
- 檢查新版本只向 GitHub 查詢版本號碼，不帶任何使用者資料（而且 play 版本沒有這個功能）。

> 如果審查時被要求更保守的填法，可以改成：
> 收集「財務資訊 → 其他財務資訊」（省錢紀錄），用途「App 功能」，**選填**、**傳輸時加密**、**不分享**、**使用者可要求刪除**。

## 2. 安全性作法

| 問題 | 回答 |
| --- | --- |
| 資料在傳輸時是否經過加密？ | 是（只連到 Google 與 GitHub 的 HTTPS） |
| 使用者是否可以要求刪除資料？ | 是：設定 →「刪除雲端資料」；手機上的資料可以解除安裝或清除儲存空間 |
| 是否已依循 Play 家庭政策？ | 不適用（目標對象不是兒童） |
| 是否經過獨立安全審查？ | 否 |

## 4. Google 雲端硬碟權限審查（OAuth）

- 使用的範圍 `https://www.googleapis.com/auth/drive.appdata` 是 Google 的**非敏感範圍**，OAuth 同意畫面發布到「正式版」時不需要 Google 的驗證審查。
- 同意畫面需要填：App 名稱、支援信箱、首頁（https://corgi8cm.github.io/SafeMoney/）、隱私權政策連結（同上）。
- 上架 Play 後，如果開啟「Play 應用程式簽署」，Google 會用**另一把金鑰**重新簽署 App：要到 Play Console →「應用程式完整性」複製那把金鑰的 SHA-1，在 Google Cloud 另外新增一個 Android 用戶端，否則從 Play 下載的版本無法登入同步。
